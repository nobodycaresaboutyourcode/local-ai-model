# challenge.txt
# hand-written emails for challenge.py. none of them come from Enron: they test whether the spam
# classifier works on mail it has never seen anything like, in the shape real email arrives in.
#
# each case is a header, a line with three dashes, then the body:
#
#   === <unique id>
#   label: legitimate | spam
#   tags: <one or more tags, comma separated>
#   subject: <subject line>
#   ---
#   <body, as many lines as you like>
#
# tags group the results. the ones used here:
#   personal      - friends and family
#   work          - everyday modern office mail
#   transactional - receipts, shipping, password resets, bills: legitimate, but shaped a lot like phishing
#   newsletter    - mail the reader signed up for
#   spammy_words  - legitimate mail full of words spam loves ("free", "won", "click here", "$")
#   format        - real-world formatting: HTML, reply chains, forwards, signatures, emoji, other languages
#   classic_spam  - the 2000s spam the training data is full of
#   phishing      - modern credential and payment scams
#   obfuscated    - spam that disguises its words (V1agra, s p a c i n g)
#   short         - very little text to go on
#
# names from a fixed list (Sarah, Mike, Jen, David, Tom, Maria, Alex, Priya) get swapped for other
# names in the invariance tests, so use them when a message needs a name.
